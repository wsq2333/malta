# 简洁工作区 UI 试验

本分支试验五项侧栏。仅修改前端，未增加自动化测试的 API、数据表、Runner 或集群部署。

| 入口 | 内部分页 |
| --- | --- |
| 测试中心 | 性能测试、自动化验证（原型） |
| 用例管理 | 性能计划、自动化套件（原型） |
| 问题管理 | 真实问题列表与详情 |
| 环境与版本 | 硬件环境、软件版本 |
| 使用指南 | 现有任务指南 |

性能测试保留原数据与操作；“已设基线”改为显示范围筛选，“对比与趋势”从该页进入。统计压缩为摘要行，版本/环境/日期筛选默认折叠，有筛选值时展开。旧 baselines、runs、trends、versions、environments 深链接继续解析，侧栏显示对应父级。

## 自动化交互原型

打开测试中心的自动化验证，可查看明确标注的虚构示例。示例展示三个结果：通过、失败和跳过；点击用例可展开断言，失败项可以打开 DEMO-001 的问题时间线。时间线可切换“待验证”“复测通过”“复测失败”状态示例，并预览保留 UID/GID 与原失败用例的复测计划。刷新后恢复初始状态。

所有示例在 AutomationPreview.tsx 中隔离，不调用测试提交、Issue 写入或报告导入 API。示例不会混入真实问题列表；新模块尚不表示实际测试能力。真实页面继续使用现有后端。

原型地址参数：`?page=automation`、`?page=suites`；示例详情分别使用 `detail=demo-run`、`detail=demo-suite`。未知详情显示未找到提示。

## 后续接入边界

需要独立实现套件修订、执行与单项结果模型、多对多 Issue 证据关联、报告解析和受控 Runner。当前 JSON 仅为展示，不是可以直接提交到现有 API 的新契约。后端接入之前不得将这些虚构结果当作修复证明。
