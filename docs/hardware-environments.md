# 硬件分类与执行快照

硬件环境页面按云厂商、区域以及各角色的机型归组。服务端、独立 Worker、测试客户端分别展示；Master/Worker 共置时按实际物理节点计数，不重复计算机器。机型相同的多条机器记录合并显示。

UID/GID、CPU/内存额度、Runner/FUSE 镜像、OS、存储、网络、挂载和采集时间属于执行快照，展示在组内。改变这些参数不会增加硬件分类。机器数量不参与分类，同一机型下的数量变化在卡片中列出，完整拓扑仍保存在快照中。这是硬件**配置类型**的分类，并不表示不同集群是同一批物理机器。

例如 sample dev 的非 root 测试、root 诊断和 CPU request 调整，对应同一类硬件：Alibaba Cloud / cn-wulanchabu，服务端与 Worker 共置于 3 台 ecs.g8i.2xlarge，测试客户端为 1 台 ecs.g8i.2xlarge。三份完整快照归在同一张卡片中。

早期仅登记服务端的快照，在云区域和已知服务端角色/机型完全一致、且只有一种候选客户端配置时，展示到对应组内并标记“客户端未登记”。存在多个候选客户端机型时不推断归属；云区域缺失时也不跨环境合并。原快照不会被补写或修改。

现有 API、Environment ID、用例和历史 Run 的引用保持不变。基线筛选明确标为“执行快照”，按硬件分类分组列出选项。硬件分类数不等于快照数。

同类机型不自动代表测试可比：比较逻辑仍核对原始快照中的拓扑、系统、配置等条件，UID/GID、资源额度或其他配置不同仍会提示差异。此次不合并数据库记录、不重写历史 plan hash，也不降低比较条件。
